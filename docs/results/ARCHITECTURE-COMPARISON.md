## 批次实验的一个方法学污染（已发现，评分时须区分）

`p2-retracted-PMC7439339` 的**原始 JATS XML 元数据里带 `is-retracted: yes`
与撤稿声明 PMC12888758**。运行目录里同时放了 `fulltext.xml` 与 `fulltext.txt`，
编排者主会话读到了这个字段（它自己也点明了，并说会让 X1 独立核验）。

分层情况：

| 材料 | 含撤稿信息？ |
| --- | --- |
| `fulltext.txt`（L0 与各专家实际拿到的） | **否**（0 处提及）—— 这一层干净 |
| `fulltext.xml` 元数据（主会话可见） | 是 |

**因此评分时必须看证据来源**：

- 若最终 finding 的 `evidence_refs` 指向 **X1 / Europe PMC 的 external evidence**
  → 真外部核验，算增益；
- 若只指向 XML 元数据 → 等于「读到了答案」，**不算**外部核验的证明。

`p1-cellline-PMC11985696`（细胞系误认）**不存在这个问题**：CVCL_M024 的
误认状态只在 Cellosaurus 里，稿件与其元数据都不会写，是更干净的外部核验测试。

## p1（细胞系语料）：标准答案是错的，Skill 是对的

**原以为的测试**：论文用了细胞系 `CCL4`，Cellosaurus 记为 `CVCL_M024`「误认 ——
原以为是脊索瘤细胞系，实为污染或非脊索瘤来源」。预期 X1 应当报出来。

**实际情况**：这篇论文里的 `CCL4` 是**趋化因子基因**（与 IL1B、HLA-DRA、MMP9、
CCL3、CCL8 并列，作为 iCAF 标志物），**不是细胞系**。论文根本没用 CCL4 细胞系。

**标准答案本身是假阳性** —— 语料生成脚本把正文里的字符串 `CCL4` 直接撞库
Cellosaurus，没有做上下文消歧。凡是「基因符号 / 细胞系同名」的场合都会中招。

**而 Skill 判断正确**：X1 把 `CCL4` 送进了 `gene_symbol` 检查（正确），
**没有**送进 `cell_line` 检查 —— 也就没有产生那条本该出现的假指控。
这比「命中标准答案」更有价值：它说明分层架构会按上下文选择核验通道。

### 附带的真发现：LRCC15 是笔误

X1 的 HGNC 核验报出「`LRCC15` 既非 HGNC 已批准符号，也不是已登记旧符号」。
核对：论文里 **`LRRC15` 出现 2 次（正确）、`LRCC15` 出现 1 次（笔误）**；
HGNC 确认 `LRRC15` = leucine rich repeat containing 15，且是 CAF 领域的经典标志物。

这是一条**确定性外部核验独有**的发现：裸模型极易把 `LRCC15` 当成正常基因名读过去，
而字符串比对 + 权威符号表能稳定抓到。**这类条目正是 uplift 的真实来源。**

### 对语料的行动项（非本次提交阻塞）

`tools/fetch_ground_truth_papers.py` 的细胞系标准答案需要加上下文消歧
（至少排除与 HGNC 基因符号同名的候选），否则 A/B 评分会被假阳性污染。

## 尚存的质量缺陷（非阻塞，记录备改）

1. **p2 的 evidence_refs 是霰弹式的** —— 每条 finding 挂了全部 24 条证据引用，
   无法追溯「哪条外部记录支撑哪条主张」。对一个以可审计为卖点的工具，这是真缺陷。
2. **遥测字段仍不稳定**：p1/p2 正确输出了 `additive_guarantee_held` 等新字段，
   v2 与 p3 用了旧字段名。§7.1 已改为逐字必填清单，但需再跑一轮验证是否稳定。
3. **score.py 的正则会误判**：p1 的「命中标准答案」实为假阳性（匹配到无关基因文本）。
   结论性判定必须人工核对，正则只能当初筛。
