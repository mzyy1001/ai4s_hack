# 架构说明：七个模块如何合成一个 Skill

## 问题：先做 7 个独立 Skill 再合并？

**结论：不要做 7 个独立 Skill。做 1 个 Skill + 7 个规则文件。**

分工照旧七个人各写各的 —— 变的不是分工，是**分工的产物形态**。

### 为什么"7 个 Skill 最后合并"会在截止日翻车

1. **交付物口径不符。** 黑客松要求的是"一个完整、可复用的 Skill 文档"。七个 Skill 需要评委自己拼装，
   拼装过程本身就是我们没做完的工作。
2. **合并成本在最后一天集中爆发。** 七个人独立设计的输出格式必然七种样子：
   有人叫 `severity` 有人叫 `level`，有人给页码有人给章节号，有人输出 Markdown 有人输出 JSON。
   周日中午前要把这些对齐，等于在最紧张的时刻做最枯燥的返工。
3. **公共前置工作会被做七遍。** 解析 PDF、切分章节、抽 n 和 p 值 —— 七个 Skill 各做一遍，
   七份互相矛盾的抽取结果，然后谁也不知道该信哪个。
4. **跨模块联动做不出来。** M7 判断结论是否成立，必须知道 M4 有没有报出"统计方法用错"。
   独立 Skill 之间没有共享状态，这层联动只能放弃 —— 而这恰恰是我们相对通用大模型的差异化价值。

### 采用的结构

```
SKILL.md                    ← 唯一入口：流程编排 + 模块路由 + 共享契约
└── references/01..07.md     ← 七份规则库，各人独立填充，互不阻塞
    schemas/*.json           ← 集成契约，先定死，不许改
```

一次公共前置（载入切分 → 结构化抽取 → 图谱解析），产出一份 `structured_result` 和一组
`figure_record`，七个模块都消费这同一份事实，再各自输出统一格式的 `finding`。

**关键性质：并行度没有损失。** 七个人依然是七个独立文件，谁写得慢不阻塞别人。
差别只在于大家写的是"规则"而不是"完整流程"。

---

## 集成契约：先定死，再各写各的

合并之所以痛苦，是因为格式在最后才对齐。所以这三件事必须**在填充规则之前**就冻结：

| 契约 | 定义在 | 作用 |
| --- | --- | --- |
| `finding` 格式 | `schemas/finding.schema.json` | 七个模块的输出长得一样，合并 = 数组拼接 |
| `locator` 定位符 | `SKILL.md §3` | 原图定位、证据回溯、去重全靠它对齐 |
| `severity` / `confidence` 枚举 | `SKILL.md §2` | 置信度评分才能跨模块加总 |

已经冻结。各模块负责人只需要做一件事：**在自己的 reference 文件里登记 category slug，
并为每条规则写清触发条件和 severity。**

`structured_result.evaluation_matrix` 是第二层黏合剂：一张固定的速查表
（有没有动物实验、有没有效能分析、最小组 n 是多少……），让 M2–M7 不必各自重读全文。
它同时也是模块路由的开关 —— 没有动物实验就不跑 M6 的动物分支。

---

## 各模块负责人实际要交什么

不需要写代码（会议共识：自然语言撰写工作流框架即可）。每人只交自己那一份 `references/0X-*.md`，
包含三样东西：

1. **规则库** —— 这个维度要查什么，逐条列出，附判定标准
2. **category slug 表** —— 每条规则的 slug + severity，登记进文件末尾的表格
3. **正例/反例** —— 每条规则至少一个"该报警"和一个"不该报警"的样例，用于回归测试

文件里已经写好了骨架和 TODO 清单，照着填即可。**不要改 `schemas/` 和 `SKILL.md §2/§3`** —— 
需要新字段就在群里提，由框架统一加，避免各改各的。

---

## 落地节奏

| 时间 | 事项 |
| --- | --- |
| 会议次日 | 各模块负责人提交 `references/0X-*.md` 初稿，线上对齐衔接逻辑 |
| 周日中午前 | 合成完整可运行版本，提交黑客松初筛 |
| 8 月底 | 入围后完成巡讲准备 |

若某模块规则梳理时间紧张：**优先覆盖核心场景**，非核心场景初筛后再补
（会议已确认的临时调整机制）。规则文件天然支持增量填充，不会阻塞整体交付 —— 
这也是"1 个 Skill + 7 个规则文件"相对"7 个 Skill"的又一个好处：
某人没写完，Skill 依然能跑，只是那一维的检查弱一些；而缺一个独立 Skill 就是整块功能缺失。

## 与会议纪要"五层审核"的映射

| 会议纪要分层 | 本架构模块 |
| --- | --- |
| 第一层 无依赖内部逻辑校验 | M2 |
| 第二层 实验方法合规性校验 | M3 |
| 第三层 统计学方法校验 | M4 |
| 第四层 论文呈现规范校验 | M5 |
| 第五层 特殊场景合规校验 | M6 |
| （全部层的输入） | M1 结构化抽取 |
| （全部层的收口） | M7 结论与讨论 |

七人分工与五层审核不是两套设计，是同一套的两个切面。
