## 二、本轮最重要的发现：skill 一度让结果变差

这是唯一一件**必须先读**的事。

### 实测设置

同一篇论文（`rct_clinical` 语料）、同一模型（gpt-5.6-sol）、同一条指令、
两个除 skill 外**完全相同**的目录。

| 运行 | 实质发现条数 | 说明 |
| --- | --- | --- |
| 裸模型基线 | **15** | 强。自己就查出了表格计数错误、表 2 与讨论的 P 值矛盾、随机后排除破坏随机化 |
| 挂 skill（修正前） | **9** | **全部是基线的真子集** —— 负 uplift |
| 挂 skill（修正后） | ~9 | 脚本终于被执行；找回了 1 条，**差距尚未补平** |

修正前漏掉的 4 条都是实质问题：阿片总剂量结论无表格支撑、
纳入 ASA I–III 但基线表只有 II/III、2 例 Horner 征使盲法可疑、
48 小时随访不足以支撑「无严重并发症」。

### 两个成因

1. **契约挤占注意力预算。** 模型先读三份 reference 才读论文，结构取代了发现。
   → 已加 `SKILL.md §2.0 Stage 0「专家通读」`：先以审稿人身份通读列全问题，
   再进契约取证；Stage 0 列出但最终丢弃的问题**必须说明原因**。
2. **确定性脚本从未被执行。** 模型把 `.py` 当资料读，六个工具贡献为零。
   → 已加 `SKILL.md §6.5「要运行，不要只读」`，给出可直接复制的调用命令。

### 由此得到的真正教训

裸模型在这个任务上**很强**。uplift 不可能来自「让它更认真」——
只能来自**它做不到的确定性计算**，而且必须**对准真实论文里实际出现的错误类型**。

证据：`statistical_forensics` 在真实论文上跑出来是空的，
因为论文的实际错误是「分类计数之和 ≠ 声明分母」（12+18=30 vs n=28），
而我写的是「计数 ÷ n 与所报百分比是否一致」——**根本不是同一个检查**。
模型只能自己临时写算术才发现它。这个缺口已补为 `table_total_mismatch`。

**它是靠实测发现的，不是靠想。** 所以 uplift 回归已加为常驻循环主题。

## 五、通宵循环怎么用

```bash
# 看进度
cat loop/state/history.md
cat loop/state/round

# 停（当前轮跑完后退出）
touch loop/state/STOP

# 重启
rm -f loop/state/STOP
nohup bash loop/night_loop.sh 30 45 > loop/logs/night.out 2>&1 &

# 跑一次 uplift 实测
python3 tools/uplift_ab.py --paper datasets/papers/rct_clinical__journal.pone.0339677/fulltext.xml
```

**改仓库前先确认循环没在跑**：`run_round.sh` 会 `git add -A`，
守卫失败时 `git reset --hard` + `git clean -fd`，未提交的改动会被卷进去或删掉。
安全做法是等 `pgrep -f run_round.sh` 为空的间隙再改。

守卫两道：路径白名单（碰 `references/02|03|05`、`datasets/`、`loop/`、`.gitignore` 即整轮回滚）
＋ 六项自检全过才提交。提案都在 `docs/proposals/`。
