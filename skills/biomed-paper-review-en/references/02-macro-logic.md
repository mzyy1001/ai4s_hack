# M2 · Macro Logic and Formal Completeness

Core question: setting biological expertise aside, does this paper — as a paper — form an auditable closed loop across research question, design, sample, methodological commitments, analysis, results, and conclusions, and is each part complete and internally consistent?

Judge the manuscript's internal formal logic and reporting closure. Do not judge whether the biological mechanism is correct, and do not automatically interpret "not reported" as "not performed."

---

## 1. Scope of Responsibility

### 1.1 What M2 Owns

- Whether the applicable sections and statements exist and whether core information can be located;
- Whether Objective, Methods, Results, tables/figures, Discussion, and Conclusion connect to one another;
- Whether population, sample, experimental materials, grouping, timeline, and analysis denominators can be closed;
- Whether key measurements or analyses explicitly committed to in Methods are accounted for in Results;
- Whether study design, sampling approach, analysis description, and claim type form a single executable contract;
- Whether the same value, unit, direction, and group name are consistent across abstract, body text, tables, figure captions, and supplementary materials;
- Data leakage or split-reporting gaps in ML/prediction models that can be confirmed from the manuscript's internal workflow;
- Whether the reference and identifier external-validation candidates already generated by X1 hold up in the manuscript's context.

### 1.2 Hand Off Without Overreaching

| Issue | Primary module | M2's handling |
| --- | --- | --- |
| Whether experimental conditions, reagents, replicate counts, animal or omics methods meet field conventions | M3 | Keep an M2 finding only when Methods and Results contradict each other; methodological inadequacy goes to M3 |
| Whether test selection, model estimation, multiple comparisons, sample size are statistically sound | M4 | M2 only judges "Methods says A, Results reports B" or a missing key-analysis description |
| Image quality, duplication, cropping, and chart presentation | M5 | M2 only judges whether figures/tables exist, are cited, and agree with body-text values or directions |
| Whether ethics approval, consent, registration, or animal authorization is compliant | M6 | M2 does only applicability and statement-existence routing; it does not substitute for the ethics judgment |
| Whether causal strength, evidence level, extrapolation, or clinical recommendations are excessive | M7 | M2 handles only the formal leap where "the conclusion's object was never measured in the study"; everything else generates M7 candidates |

Each issue gets exactly one primary category that best expresses the root cause. Never output "category A / category B." If other modules or secondary phenomena are also involved, write them into related_categories or suggested_modules for Layer 4 to merge.

## 2. Inputs and Evidence Gating

### 2.1 Inputs

- structured_result_v2, focusing on article_design.primary_design, design_components, objective, claims, key_data, gaps, and evidence_refs;
- The cross-section pack, references pack, statements pack, and lightweight global context;
- Body-text sectioning, table/figure inventory, and accessible supplementary materials;
- Deterministic-tool or X1 candidates; candidates and signals cannot be treated directly as findings.

If structured_result still contains unresolved items, hand back to M1 for parsing first; do not guess key fields on your own.

### 2.2 Manuscript-Source Filtering

Only author-manuscript content can prove "what the paper reports":

- Accept: front, body, and back of the JATS article, supplements directly linked from the body and accessible, and the body text, tables/figures, statements, and references that belong to the paper within the PDF;
- Exclude by default: sub-article, response, decision letter, peer-review, reviewer report, editor report, author response, acceptance letter, production query, correction request, and their nested content;
- Include these sources as evidence only when the review material itself is the object of study, or the user explicitly requests analysis of the review process;
- An editor's or reviewer's request that authors add something proves only that "someone made the request," not that the body text now contains or lacks that content;
- When an author response claims "revised," one must still return to the final body text to locate the revision.

When parsing JATS, filter by XML element boundaries first; never simply flatten the whole XML to plain text and search it globally. If the parser cannot distinguish body text from review attachments, register a system_limitation and make no high-confidence judgment about the affected absences or contradictions.

### 2.3 Absence and Inaccessibility

"Not reported" must carry absence evidence:

1. State the applicable study component;
2. List the search scope, including body text, tables, figure captions, statements, and accessible supplementary materials;
3. List the concept and its synonym search terms;
4. Record zero hits or hits only in irrelevant sources;
5. Rule out merged sections, alternative headings, and cross-references.

When a source is unreadable, supplementary materials are inaccessible, a registration page is unreachable, or parsing fails, only a system_limitation may be registered. Never count a system-capability limitation as a defect of the paper.

### 2.4 Confidence

- confirmed: positive evidence in the manuscript, or auditable absence evidence, is sufficient support;
- likely: multiple clues agree but one key locator is still missing;
- uncertain: design classification, source attribution, or textual meaning is ambiguous.

For likely or uncertain, review_confidence is at most medium. A single extraction signal, a directory name, a folder name, or a dataset slot name cannot determine the study design.

## 3. Route by Study Component First

First identify the design_components, then review each component, and finally check how the components converge on the overall objective and overall conclusion. A mixed study must not be collapsed into a single study_type, nor share one unexplained denominator.

| Component | M2's minimal closed loop |
| --- | --- |
| RCT/interventional study | Recruitment → randomization/allocation → intervention → follow-up → analysis population → prespecified endpoints → results |
| Cohort/cross-sectional/case-control | Source population → inclusion-exclusion/sampling/matching → exposure and outcome → denominator → analysis → association claim |
| Diagnostic study | Enrollment → index test → reference standard → evaluable samples → diagnostic metrics |
| Systematic review/aggregate meta | Question framing → search → screening → included studies → synthesis → conclusion |
| IPD meta-analysis | Cohort identification → IPD acquisition/harmonization → individual-level inclusion-exclusion → per-cohort and total denominators → one-stage or two-stage analysis → synthesis |
| Scoping/rapid review | Scoping question → search sources → screening/charting → evidence map; do not force effect-size meta requirements |
| Secondary analysis of a public database | Database/version/time window → variable definitions → inclusion-exclusion → final cohort → analysis → conclusions within the database population |
| Animal/laboratory/omics/in-silico | Material or data source → groups/treatments → explicit measurements → analysis outputs → corresponding results |
| ML/prediction model | Samples and labels → split units → within-fold preprocessing/selection → training and tuning → independent evaluation → performance claim |
| Mixed study | Each component closes on its own, with explicit inter-component interfaces; one component's result must not masquerade as another component's validation |

Routing guardrails:

- An IPD meta-analysis is not an ordinary aggregate meta; do not flag it merely for lacking a traditional forest plot, pooled effect, or the standard PRISMA elements;
- When a rapid/scoping review coexists with a pilot study, keep a separate search-and-screening ledger and a separate participant-flow ledger;
- Studies on public, de-identified databases are not automatically flagged for lacking case-by-case informed consent; hand to M6 to judge by database policy and waiver context;
- Purely in-silico studies are not subject to human consent or animal approval;
- Whether the methodological parameters of animal, experimental, and computational components are adequate is for M3/M4; M2 does not run hard-threshold checklists for Western blot, flow cytometry, IHC, RNA-seq, toxicology, or dose-point counts;
- When there is no ML/prediction component, record not_applicable once in coverage; do not enumerate every leakage type item by item.

## 4. The Four Mandatory Reconciliation Ledgers

Do not start from abbreviations, section subheadings, or format checklists. In the first pass, build the following four lightweight ledgers; when the budget is short, prioritize keeping the ledgers and the critical/major findings.

### 4.1 Population, Materials, and Denominator Ledger

Record per component:

| Stage | Subjects/source | Inclusion or selection rule | n | Exclusions/missing | Downstream use | Evidence |
| --- | --- | --- | --- | --- | --- | --- |
| Source set |  |  |  |  |  |  |
| Screening/QC |  |  |  |  |  |  |
| Grouping/matching/validation |  |  |  |  |  |  |
| Final analysis |  |  |  |  |  |  |

Human studies track screening, diagnostic verification, randomization, loss to follow-up, and analysis sets; experimental studies track samples/animals/sections/cells or datasets and their hierarchy; reviews track records, full texts, studies, cohorts, and individuals — these denominators must never be mixed.

### 4.2 Methods→Results Commitment Ledger

Extract completed-tense commitments from Methods, such as was measured, was assessed, was performed, was determined, we evaluated, variables entered into the model. For each, record:

- Object, time point, and analysis level;
- Relationship to the primary objective, grouping, main conclusion, or safety;
- Corresponding location in Results, tables/figures, or supplementary materials;
- If unreported, whether cancellation, missingness, or QC failure was explicitly explained.

A broad list of "collectible variables" is not a commitment to report all of them; only items explicitly completed and bearing on objectives, grouping, interpretation, or claims enter the core ledger.

### 4.3 Analysis→Claim Ledger

Map claims to actual results and analysis levels:

| Claim type | Manuscript-internal interfaces that must be located |
| --- | --- |
| frequency/prevalence/incidence | Whether source population, observation window, numerator, and denominator come from the same sampling frame |
| associated factor | The corresponding comparison or model, effect direction, and population |
| independent predictor | An adjusted model exists; variables and adjustment level are identifiable |
| diagnostic performance | Index test, reference standard, and the same evaluable sample |
| causes/reduces/improves | Whether a corresponding intervention/temporal ordering exists; evidence strength goes to M7 |
| safe/effective | Whether the corresponding efficacy and safety endpoints were actually measured and reported |

### 4.4 Cross-Source Numeric Ledger

For the main sample sizes, denominators, endpoints, effect sizes, P values, CIs, units, time points, and directions, merge candidate values from Abstract, Results, tables, figure captions, and supplementary materials. First check:

- Whether they belong to different analysis populations, time points, or units;
- Whether it is merely reasonable rounding;
- Whether percentages use different but stated denominators;
- Whether the table's overall value can be reasonably derived from mutually exclusive subgroup values;
- Whether the point estimate falls inside its confidence interval.

Only candidate conflicts that cannot be explained become findings.

## 5. Main-Chain Rules

### 5.1 Objective Not Closed

Category: objective_drift

Holds when a primary objective or hypothesis explicitly stated in the Abstract/Introduction has no corresponding measurement or analysis in Results, tables/figures, or accessible supplementary materials.

Does not hold:

- The result exists but its evidential strength is questionable — hand to M7;
- A secondary background question has no dedicated result;
- The objective was reasonably revised and the manuscript explains why.

Severity:

- major: one primary objective goes entirely unanswered;
- critical: the sole primary objective has no results at all, leaving the paper's core uninterpretable;
- minor: an explicitly listed secondary exploratory objective is unaccounted for.

### 5.2 Methods Commitment Unaccounted For

Category: methods_results_gap

A key measurement, endpoint, sensitivity analysis, model, group verification, or safety assessment that Methods explicitly claims was completed has no result in any Results source and no explanation.

Positive example: Methods states that severity was graded per GOLD and pulmonary function testing was completed; Results reports no grading, no pulmonary function, and no reason for the missingness — while this information bears on the study population and the main risk claim.

Negative example: Methods states prior-medication data were collected; Results explicitly reports insufficient completeness and provides the available distribution in the supplement.

Severity:

- critical: the primary endpoint or the sole core verification is entirely missing, leaving the conclusion uninterpretable;
- major: a key grouping, main safety outcome, core covariate, or prespecified analysis is missing;
- minor: a secondary exploratory commitment that does not change the main inference is missing.

### 5.3 Results Become Islands

Category: orphan_results

A material orphan result is a data block in Results substantial enough to change the paper's topic or support a main conclusion, yet with no origin, motivation, or analysis plan in the study objectives/Methods. The Discussion merely failing to restate every result does not constitute a major finding.

- major: a new population, experimental component, primary endpoint, or analysis appears out of nowhere and is used for a core conclusion;
- minor: a secondary result goes unexplained, hurting readability but not altering the main chain.

### 5.4 Design→Sampling→Analysis→Claim Rupture

Category: design_analysis_disconnect

Within the manuscript's own description, study design, sample formation, verification pathway, analysis, or claims cannot all hold simultaneously. For example:

- Claiming census/consecutive enrollment of all patients on one hand, while selecting cases or controls at a fixed ratio from a larger source population on the other, without providing that source population;
- Computing population frequency/prevalence directly from a case-control-style or matched analysis sample;
- Verifying the diagnostic result only in highly suspected individuals while presenting the denominator as the whole population;
- A matched/paired/clustered/repeated design with no statement of how the analysis carries that structure;
- The sample or results of one mixed-study component being treated as validation of another component;
- An IPD meta conflating cohort count, individual count, and analysis-available individuals into a single denominator.

If the design chain is intact and only the statistical method may be inappropriate, hand to M4. If the main problem is unreported key fields of an adjusted model, analysis_reporting_gap may be chosen as the primary category, without also filing design_analysis_disconnect.

### 5.5 Participant Flow, Sample Flow, or Denominator Not Closing

Category: participant_flow_inconsistency

Screening, enrollment, grouping, matching, verification, exclusion, loss-to-follow-up, and final analysis counts cannot be reconciled with one another through the manuscript's explanations, or the same endpoint uses unexplainably different denominators in body text versus tables/figures.

- major: affects the primary endpoint, frequency, safety, or main analysis population;
- minor: one editorial denominator discrepancy in a secondary table;
- critical: it is impossible to determine which analysis set any core result comes from.

If the analysis sets are clearly defined and the question is whether the chosen statistical strategy is correct, hand to M4.

### 5.6 Unexplained Changes in Endpoints, Time Points, or Analysis Populations

Primary categories — choose one of three by root cause:

- endpoint_switching: an unexplained change in primary/secondary endpoints or time points;
- analysis_population_mismatch: ITT, PP, safety set, or another analysis population is inconsistent across the manuscript;
- selective_reporting: only the favorable part of a prespecified set of analyses is reported, with positive evidence that the rest exist.

Reconcile against the registration or protocol when available; register a system_limitation when inaccessible. Never infer selective reporting merely because a commonly reported outcome is absent.

A core endpoint being replaced, concealed, or selectively reported can be critical; insufficient explanation of secondary endpoints or analysis sets is usually major.

### 5.7 Internal Conflicts in Values, Units, Directions, and Timelines

Primary category: internal_inconsistency

Observations under the same grouping key cannot all hold across Abstract, body text, tables, figure captions, or supplement. The grouping key includes at least study component, analysis population/material, group, time point, endpoint, and unit.

The following more specific categories replace internal_inconsistency only when they accurately express the root cause:

- abstract_main_text_inconsistency;
- timeline_inconsistency;
- statistical_method_mismatch, restricted to a contradiction between the test claimed in Methods and the form of the statistic actually reported in Results.

Multiple conflicts from the same root cause are clustered into one finding listing all evidence — do not count repeatedly per table cell. Whether the values are statistically plausible goes to M4; a discrepancy between body-text and table statements belongs to M2.

### 5.8 Narrow-Sense Circular Reasoning

Category: circular_reasoning

Holds only when the conclusion to be proven directly determines key sample selection, labels, grouping, or evaluation rules, and the same rule is then used to prove that conclusion. For example, selecting subjects by "drug-sensitive" first, then using those subjects to prove the drug works.

The following do not automatically qualify:

- Conventional disease-model selection;
- The Discussion offering mechanistic interpretation of results;
- Post-hoc subgroups explicitly labeled exploratory.

### 5.9 Formal-Level Conclusion Leaps and Handoff to M7

Category: conclusion_overreach is used only for formal leaps where the study contains no corresponding object or level at all, for example:

- Only in vitro data, yet directly claiming improved clinical outcomes in patients;
- Only animal data, yet claiming efficacy proven in humans;
- Only one marker measured, yet claiming full validation of multiple unmeasured pathways;
- No safety measurement of any kind, yet declaring safety.

Whenever a relevant experiment or analysis exists but may be insufficient due to design, sample size, confounding, surrogate endpoints, or evidence level, M2 does not file this finding; it instead generates a possible_unsupported_claim or possible_causal_overreach candidate for M7, attaching the verbatim claim, locator, design, and actual results.

### 5.10 ML/Prediction-Model Interfaces

Run only when design_components includes ML, prediction, classification, risk scoring, or benchmark. Check six interfaces:

1. Independent split units — sample/patient/section/site/time, etc.;
2. Whether the same entity or a derived sample crosses training, validation, and test sets;
3. Whether normalization, imputation, feature selection, and dimensionality reduction are fitted only on training data/training folds;
4. Whether tuning and model selection are isolated from the final test set;
5. Whether features contain information from after the prediction time point or label-derived information;
6. Whether external validation is genuinely independent of the development data and development decisions.

Adjudication tiers:

- Clear evidence of overlap, whole-data fitting, test-set tuning, or future/label information: file a finding under the specific data_leakage_* category, major or critical depending on whether the main performance is contaminated;
- Merely failing to report split units, preprocessing order, or independence: data_split_not_reported, usually major; must not be written as "leakage has occurred";
- Code, supplement, or data inaccessible: system_limitation;
- No ML component: one not_applicable line in coverage.

## 6. Structural and Editorial Completeness

Run this section only after the main-chain checks are complete. Judge sections by information function, not literal headings; a merged Results and Discussion, or a Conclusion inside the Discussion, counts as present.

### 6.1 Core Structure

| Manuscript component | Information typically required | Adjudication guardrails |
| --- | --- | --- |
| Abstract | Objective, design/materials, main results, conclusion | An unstructured abstract is not flagged for lacking subheadings |
| Introduction | Problem, gap, objective | Background length does not equal completeness |
| Methods | Design, subjects, procedures, measurements, analysis | Field-specific parameters go to M3/M4 |
| Results | Results corresponding to the primary objectives | Interpret review-type articles per their article type |
| Discussion/Conclusion | Interpretation, limitations, answer to the objectives | May be merged; a standalone Conclusion is not mandatory |
| Funding/COI | A statement, or an explicit "none" | Judge by journal and manuscript type |
| Data availability | A statement or an access path | With no journal/funder policy given, record as pending confirmation only — no automatic finding |
| References | In-text citations and entries correspond | Citation authenticity relies on X1 |

Use missing_section only when the component genuinely applies, a full-text absence search has been completed, and the information function is also absent. A substantive absence of Methods or Results can be critical; an Introduction/Discussion absence that affects interpretation is usually major; journal-dependent or editorial statements are usually minor or pending confirmation.

Applicability of human/animal ethics, consent, and registration is ultimately adjudicated by M6. Public de-identified databases, public omics data, purely in-silico studies, reviews, and meta-analyses must not be held to the consent requirements of primary human research.

### 6.2 Abstract

incomplete_abstract is for an abstract missing objective, basic design/materials, main results, or conclusion information. The mere lack of structured subheadings is not a finding. An abstract omitting main numbers can be minor/major by impact; an abstract conflicting with the body text uses abstract_main_text_inconsistency.

### 6.3 Figures/Tables, Terminology, and Citations

- missing_figure_reference: a figure/table cited in the body does not exist; major when a main result depends on it, otherwise minor;
- orphan_figure: a figure/table is cited neither in the body nor collectively in supplementary materials, usually minor;
- terminology_inconsistency: changes in group, endpoint, material, or entity names cause genuine mapping ambiguity; pure stylistic variation is not flagged;
- abbreviation_undefined: a non-standard abbreviation is undefined at first occurrence, minor;
- reference_numbering_error: run only for a confirmed numeric-order citation system; author-year systems are not checked for sequential numbering.

Bundle these editorial items in the output; they must not crowd out critical/major logic issues.

### 6.4 Reporting Guidelines

CONSORT, STROBE, STARD, PRISMA, PRISMA-IPD, PRISMA-ScR, ARRIVE, TRIPOD, and the like are used only to identify "which interface the current component might be missing" — they are not a unified severity table.

missing_reporting_guideline_element requires all of the following:

1. The guideline and version are confirmed applicable to this specific study component;
2. The missing item is required, not merely recommended;
3. An absence search has been completed;
4. The finding explains how the absence affects flow, denominators, interpretation of the primary endpoint, or verifiability.

Severity is decided by actual impact. Never flag every missing CONSORT/PRISMA/ARRIVE item as critical, and never substitute a guideline checklist for the expert judgment of M3, M4, or M6.

## 7. External Validation Candidates

M2 only consumes external_validation_candidate items already generated by X1; it never claims on its own to have performed successful online validation.

| X1 check_type | M2 primary category | Condition for holding |
| --- | --- | --- |
| `cited_work_retracted` | cites_retracted_work | A retracted work is used as valid support and the manuscript does not note the retraction status |
| `reference_doi_resolves` | reference_not_resolvable | The authoritative source definitively fails to resolve it and typographical error has been ruled out |
| `gene_symbol_excel_corruption` | gene_symbol_data_corruption | Date-converted symbols appear in the actual data or results |
| `gene_symbol_outdated` | gene_symbol_outdated | The obsolete symbol creates entity-mapping risk; usually minor |
| `gene_symbol_unrecognized` | gene_symbol_unrecognized | The authoritative source does not recognize it and manual context re-review remains in doubt |
| `variant_position_range` | variant_inconsistent_with_reference | With the manuscript's species and transcript/protein version matched, the position still exceeds the range |
| `variant_reference_residue` | variant_inconsistent_with_reference | With the manuscript's species and transcript/protein version matched, the reference residue still conflicts |

Citing a retracted paper to discuss the retraction event itself is not an error. External-service timeouts or missing access rights are registered only as system_limitation.

The deterministic tools' count_percentage_mismatch and table_total_mismatch may serve as candidates; after checking back against the manuscript, M2 characterizes them as internal_inconsistency or participant_flow_inconsistency.

## 8. Severity and Deduplication

Severity is determined by the actual impact on the paper's main chain, not by rule names or reporting-guideline names:

- critical: the sole core objective/main result is uninterpretable, the core analysis set is unidentifiable, or clear data-integrity contamination invalidates the main performance;
- major: an evident rupture in a primary objective, denominator, flow, key commitment, main value, or analysis→claim interface, requiring substantive supplementation or reanalysis;
- minor: editorial, local-explanation, or secondary-result gaps that do not change the current core inference.

Denoising rules:

1. One finding per root cause;
2. One primary category per finding;
3. Put "nothing found" and not_applicable into a compact coverage table, not long prose;
4. absence, inaccessible, and confirmed leakage must be explicitly distinguished;
5. Finding count is not the goal; prioritize the breakpoints that first block the main conclusion.

## 9. Output Requirements

### 9.1 Review Order

1. Filter out non-manuscript sources;
2. Identify all design_components;
3. Build the four ledgers;
4. Run the critical/major main-chain checks;
5. Route M3/M4/M5/M6/M7 candidates;
6. Do minor structural and editorial checks last;
7. Deduplicate candidates and bind evidence_refs.

### 9.2 The Final Answer Must Answer Directly

- Whether the structure is complete; if not, whether the gaps genuinely apply;
- Whether the core logic chain closes;
- What breakpoint first blocks the main conclusion;
- Which conclusions still need re-review by M7 or other modules;
- Which judgments are constrained by inaccessible sources.

Recommended summary template:

"The structure is essentially complete / has X applicable gaps; the core logic chain closes / partially closes / does not close. The primary breakpoint lies at A→B: the manuscript claims …, but …, so the main claim … cannot currently be self-consistently supported from within the manuscript."

### 9.3 Minimal Content of Each finding

- A single primary category and severity;
- The specific problem, not a generic checklist;
- At least one present evidence; absence issues additionally carry absence evidence;
- The affected objective, result, or conclusion;
- An actionable revision suggestion;
- review_confidence;
- Finding origin;
- If cross-module, write suggested_modules instead of filing duplicates.
